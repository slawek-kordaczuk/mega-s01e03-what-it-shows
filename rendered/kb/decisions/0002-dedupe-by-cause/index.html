Parser: day-first dates read month-first

The shared parser interprets dates as MM/DD even when the tenant uses day-first dates. For example, harbour.dental uses en-GB and booking-v2; R-41200 describes 7 April becoming 4 July. The adjacent R-41201 corrects that account in the other direction. Their wording differs, but the tenant and input path identify the parser cause.

This group includes app and email reports, plus forms whose hint already agrees with the tenant locale. Keep a parser ticket for this group. Fix the shared parser to respect the tenant’s date order, reject ambiguous input where appropriate, and test app, email, and booking-v2 paths. Verify both ambiguous dates and dates with a day greater than twelve.

Hint: booking-v3 tells people to use the wrong order

For day-first tenants using booking-v3, the form prints MM/DD/YYYY while interpreting input using the tenant’s day-first order. Following the displayed hint therefore produces the wrong date. This is a separate UI/input contract bug, not a duplicate parser report.

Examples are R-41230 (copper.studio, es-ES), R-41241 (alder.physio, de-DE), and R-41251 (pale.harbour, pt-PT). All came through the form. Use a separate ticket: make the displayed hint and parser agree with the tenant locale; test all affected booking-v3 locales. A shared-parser fix alone does not establish that this hint is correct.

Keep uncertainty visible

Reports R-41202, R-41209, R-41236, R-41344, and R-41620 have unusual one-day or timing descriptions. The supplied cause logic and desk notes keep them under the parser group by tenant and channel. Preserve their IDs and descriptions for follow-up; do not invent a proven timezone cause from prose alone, and do not silently drop them.

Decision proposed: merge only when the cause matches

  1. Deduplicate export rows by report ID before counting; repeated rows are not new reports.
  2. Look up the tenant’s locale and booking form. Do not use browser locale or the intake tag as the diagnosis.
  3. Apply causeOf from src/lib/kb/causes.ts, using the report channel and tenant record.
  4. Merge only reports with the same established cause. Equal subject lines are neither necessary nor sufficient.
  5. Keep unknown tenants or unclassified reports separate for investigation. Missing evidence is not a merge rule.
  6. Record report IDs and counts on each ticket; reclassify new reports as they arrive.
